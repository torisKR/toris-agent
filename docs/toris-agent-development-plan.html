01 · Executive Summary

개발·운영·성장을
하나의 검증된 실행으로 만든다.

Toris Agent는 Claude와 Codex를 지휘하는 개발 하네스를 중심으로, Telegram·Slack·Notion을 연결해 아이디어 수집, 작업 관리, 시장 조사, 상품 기획, 개발, 콘텐츠, 고객, 운영, 법무·회계 준비를 승인 가능한 Workflow로 묶는 1인 개발자용 Solo Founder Agent OS다.

Build
Code

프로젝트별 AI 세션, worktree, 리뷰, 테스트와 릴리스를 관리한다.

Operate
System

Inbox, Task, SOP, 승인, 유지보수와 백오피스를 반복 가능한 운영 체계로 만든다.

Grow
Revenue

문제 신호부터 상품·브랜드·랜딩·콘텐츠·실험·매출 학습까지 연결한다.

Control
1 Receipt

근거, 비용, 승인, 변경, 게시와 전달 결과를 실행 영수증으로 남긴다.

제품 한 문장: Toris Agent는 혼자 회사를 운영하는 개발자가 여러 AI와 업무 도구를 한곳에서 지휘하고, 아이디어를 검증된 코드·콘텐츠·운영·수익화 자산으로 전환하게 하는 로컬 우선 오픈소스 에이전트 운영체제다.

03 · Problem & Opportunity

1인 개발자는 제품을 만들면서
회사 전체를 동시에 운영한다.

현재의 문제

  • 코드는 저장소에, 결정은 Notion에, 요청은 Telegram·Slack에 흩어진다.
  • Claude와 Codex 세션마다 승인·비용·복구 방식이 다르다.
  • 개발, 시장 조사, 콘텐츠와 고객 피드백이 공통 목표로 연결되지 않는다.
  • 아이디어는 계속 늘지만 WIP와 중단 기준이 없어 프로젝트가 정체된다.
  • 매출·전환·이탈·AI·클라우드 비용을 프로젝트별로 보기 어렵다.
  • 반복 업무 자동화에 실패·재시도·예외·책임 경계가 부족하다.
  • 법무·회계·세무 준비가 마감 직전에 수동 정리 작업으로 몰린다.

Toris의 기회

  • 모든 입력을 하나의 Founder Inbox와 Project/Run 모델로 정규화한다.
  • 28개 전문 Agent Profile을 필요할 때만 조합해 가상 조직처럼 사용한다.
  • 개발 작업을 고객 문제, 실험, 지표와 수익 목표에 연결한다.
  • 채팅에서는 명령·승인을, Notion에서는 계획·산출물·SOP를 관리한다.
  • 성공한 Run을 Recipe, Skill, SOP와 템플릿으로 재사용한다.
  • 외부 게시·배포·지출·법률·세무 행동은 명시적 Gate를 거친다.
  • 프로젝트를 시작하는 것뿐 아니라 Pause/Kill 결정을 돕는다.
04 · Goals & Scope

비전은 1인 개발자 운영체제,
첫 구현은 안전한 실행 코어다.

Goals

제품이 반드시 해야 하는 것

  • 여러 프로젝트, Inbox, Run, Agent, 지표와 승인을 전역에서 관리한다.
  • Claude와 Codex를 공통 AgentAdapter와 이벤트 계약으로 실행한다.
  • Telegram·Slack 입력을 안전하게 수집하고 모바일·채널 승인 표면을 제공한다.
  • Notion에 조사·계획·콘텐츠·SOP·결정·receipt를 구조화해 동기화한다.
  • 28개 Agent Profile과 재사용 Skill을 권한·입출력 schema·eval과 함께 배포한다.
  • 프로젝트 포트폴리오, WIP, stale review와 Kill/Continue 기준을 관리한다.
  • Revenue Cockpit과 Experiment Engine으로 작업을 고객·수익 학습에 연결한다.
  • Daily·Weekly·Monthly Routine과 단계별 Autonomy Level을 제공한다.
  • 테스트·근거·delivery receipt가 없는 작업을 완료로 처리하지 않는다.
Non-goals · Initial Release

처음에는 하지 않는 것

  • 전문가 검토 없는 법률 자문, 세무 신고, 회계 장부 확정
  • 승인 없는 송금, 환불, 광고비 집행, 외부 게시, production 배포
  • 완전한 ERP·CRM·회계 프로그램 또는 법무 서비스 대체
  • 다중 사용자 SaaS와 조직 전체 권한 관리
  • 28개 Agent를 무제한으로 상시 실행하는 자율 swarm
  • 무제한 자율 CEO처럼 사업 방향·가격·지출을 스스로 확정하는 것
  • 채팅이나 Notion에 provider token과 운영 secret을 저장하는 것
  • 처음부터 Desktop을 핵심 런타임으로 만드는 것
범위 제어: 먼저 실행·승인·증거 코어를 완성하고, Connector·Founder 기능·Agent Pack을 동일한 계약 위에 단계적으로 올린다.
05 · Product Principles

모델은 판단하고,
런타임은 통제한다.

01

Local-first

코드, worktree, 로그, 실행 상태와 승인은 사용자의 장비에 보관한다.

02

Provider-agnostic

역할과 모델을 분리한다. reviewer는 역할이고 Opus는 정책 선택이다.

03

Deterministic control

재시도, 비용, 병렬 수, 경로 잠금, 완료 조건은 코드가 집행한다.

04

Evidence-first

대화가 아니라 diff, 명령 exit code, 테스트와 commit을 결과로 취급한다.

05

Safe by default

읽기 전용이 기본이며 쓰기·네트워크·push·merge·deploy는 정책과 승인을 거친다.

06

Small public surface

핵심 Skill과 역할은 작게 유지하고 추가 기능은 Recipe pack으로 분리한다.

핵심 불변식: LLM은 실행 계획과 수정안을 제안할 수 있지만, 승인 없이 권한을 확대하거나 완료 조건을 낮추거나 보호된 경로를 우회할 수 없다.

07 · Solo Founder OS

1인 개발자에게 필요한 것은 더 많은 대화창이 아니라,
무엇을 만들고 무엇을 버릴지 결정하는 운영 루프다.

Toris는 “바쁜 일을 대신하는가”보다 고객 문제를 더 빨리 발견하고, 검증 비용을 낮추며, 매출과 유지보수의 누수를 줄이는가를 기준으로 기능을 설계한다.

01 · Founder Inbox

모든 생각과 요청을 한곳에

Telegram 음성·텍스트·링크, Slack thread, Notion 변경을 Idea, Task, Customer Signal, Approval로 분류한다.

02 · Portfolio & WIP

시작보다 중단을 돕는다

매출 가능성, 검증 신뢰도, 제작 비용, 유지보수 부담을 비교하고 진행 중 프로젝트 수를 제한한다.

03 · Outcome Contract

모든 Run을 사업 결과와 연결

목표 고객, 기대 행동, 지표, 마감, 비용 상한, 수용조건과 다음 결정을 먼저 고정한다.

04 · Founder Context

검토 가능한 사업 문맥

기술 스택, 브랜드 톤, 수익 목표, 가용 시간, 위험 성향과 금지 행동을 버전 관리한다.

05 · Opportunity Radar

아이디어보다 문제 신호

고객 불만, 검색 의도, 경쟁 변화, 커뮤니티 질문을 근거·날짜가 있는 Opportunity Card로 축적한다.

06 · Customer Voice Hub

문의와 이탈 신호를 제품 학습으로

지원, 인터뷰, 리뷰, 기능 요청을 고객·문제·빈도·매출 영향으로 묶는다.

07 · Revenue Cockpit

매출보다 이익과 생존 기간

MRR, 전환, 이탈, AI·클라우드 비용, 프로젝트별 공헌이익, runway와 세금 준비금을 본다.

08 · Experiment Engine

기능과 콘텐츠를 학습 단위로

가설, 대상, 변형, 지표, 관찰 기간, 중단 조건과 결과를 다음 의사결정에 연결한다.

09 · Release & Incident

출시 이후까지가 개발

release checklist, 관측 창, 장애 triage, rollback 제안, postmortem과 재발 방지를 연결한다.

10 · Knowledge & Decisions

문서가 아니라 결정 근거

출처, 기준일, 신뢰도, 만료일, 상충 근거와 최종 의사결정을 Notion과 로컬 artifact에 연결한다.

11 · Operating Rhythm

매일·매주·매월 반복

아침 Brief, 종료 Review, 주간 Founder Review, 월 마감 준비를 자동 생성한다.

12 · Asset Factory

성공한 일을 재사용 자산으로

완료 Run을 Recipe, SOP, Skill, 템플릿, 코드 모듈과 콘텐츠 재가공 규칙으로 추출한다.

11 · Orchestration Model

Fable은 계획하고,
Toris가 집행한다.

표준 Team Run

Workspace Snapshot

base commit, dirty files, 프로젝트 규칙, build/test 명령, 보호 경로를 고정한다.

Spec & Plan

요구사항을 목표·비목표·수용조건으로 바꾸고, Fable이 구조화된 Task DAG를 제안한다.

Plan Gate

경로 겹침, 권한, 비용, 검증 명령을 코드로 검사하고 필요한 경우 사용자 승인을 요청한다.

Parallel Execution

독립 작업만 병렬 배치하며 writer마다 별도 worktree와 branch를 생성한다.

Cross-provider Review

Codex 작성 결과는 Claude가, Claude 작성 결과는 Codex가 우선 검토한다.

Deterministic Verification

lint, typecheck, test, build, 변경 범위, secret 검사 결과를 실제 exit code로 판정한다.

Integration & Receipt

commit을 통합 worktree에 적용하고 전체 검증 후 실행 영수증을 생성한다.

병렬 실행 규칙

Allowed
  • 서로 다른 프로젝트의 독립 작업
  • 읽기 전용 분석 작업 여러 개
  • 소유 경로가 겹치지 않는 writer 작업
  • 구현과 독립 문서·테스트 분석
Blocked or serialized
  • 동일 파일을 수정하는 두 writer
  • 공통 인터페이스 확정 전의 의존 구현
  • 마이그레이션과 이를 전제로 한 기능 변경
  • 동일 branch 또는 working directory 공유
완료 공식: Acceptance criteria 충족 + 결정론적 검증 통과 + 변경 증거·commit 존재. 모델의 “완료” 메시지는 참고 정보일 뿐 완료 상태를 직접 만들지 못한다.

16 · Operating Rhythm & Autopilot

AI는 계속 일해도,
창업자는 정해진 순간에만 개입한다.

1인 개발자의 희소 자원은 token이 아니라 주의력이다. Toris는 알림을 늘리지 않고 승인과 의사결정을 묶어서 전달하며, 저위험 반복 작업만 제한적으로 자동 실행한다.

Daily

아침 Brief · 저녁 Close

  • 오늘의 3대 결과와 승인 대기
  • 매출·오류·고객 신호 이상만 강조
  • 완료·차단·학습·내일 첫 작업 기록
Weekly

Founder Review

  • 출시와 고객 반응 검토
  • 매출 가능성·유지 비용·WIP 재평가
  • Build·Grow·Operate 각 1개 결과 선택
Monthly

Close & Reset

  • 거래·구독·AI·클라우드 비용 정리
  • 보안·백업·dependency·복구 점검
  • 실험 회고와 Kill/Continue 결정

자동화 계약

  • 주요 읽기·실행 명령은 모두 --json을 지원한다.

20 · Security & Permissions

권한은 에이전트에게 주는 것이 아니라
작업에 임대한다.

기본 보안 정책

  • 모든 세션은 read-only에서 시작한다.
  • writer는 허용 경로와 전용 worktree에서만 쓴다.
  • 네트워크는 기본 차단하고 명시적 policy로 연다.
  • API 키는 provider 프로세스에만 일시 주입한다.
  • 명령 로그와 이벤트에서 secret을 redaction한다.
  • push, merge, publish, deploy는 기본 승인 대상이다.

승인 Gate

  • 계획 승인
  • dependency 설치 또는 major upgrade
  • 프로젝트 외부 파일 접근
  • 네트워크 쓰기와 외부 API 변경
  • DB migration과 production 데이터 접근
  • 대량 삭제 또는 위험한 shell 명령
  • Git push, PR 생성, merge, 배포

  • 승인 대기열과 OS 로컬 알림
  • lint/typecheck/test/build evidence
  • stop, retry, resume, crash recovery
  • 구조화 JSON/JSONL 출력

MVP 제외

  • Desktop 앱
  • 클라우드 원격 worker
  • 조직·팀 사용자 관리
  • Slack/GitHub App 완전 통합

MVP 완료 조건

  • 세 개 이상의 프로젝트를 등록하고 전역 TUI에서 동시에 볼 수 있다.
  • Claude와 Codex 각각 하나 이상의 세션을 공통 이벤트로 실행·재개·중단할 수 있다.
  • writer 두 개가 동일 경로를 소유하려 하면 스케줄러가 병렬 실행을 차단한다.

  • 검증 실패 run은 completed로 전환되지 않는다.
  • 모든 성공 run에 base SHA, result SHA, commands, results가 포함된 receipt가 존재한다.

병렬 writer
writer마다 별도 Git worktree. 소유 경로가 겹치면 직렬화한다.
완료 기준
수용조건 + 검증 명령 + commit/evidence가 모두 있어야 completed.
상태 저장
SQLite + append-only event log + 파일 artifact.
외부 제어
JSON/JSONL CLI, JSON-RPC socket, WebSocket, MCP server를 단계적으로 제공.
MVP 초점
Issue 또는 자연어 목표를 검증된 patch/commit으로 변환하는 vertical slice.

Autonomy

포트폴리오
프로젝트별 WIP limit, stale review와 Kill/Continue 기준을 제공한다.
